# 01 需求与范围

## 1. 题目依据与解释

下表“题目要求”来自用户提供的课件照片；“实施解释”是便于验收的设计选择，并非照片逐字要求。

| 题目要求 | 可演示的实施解释 |

| 存储管理器：按关系数据模型在磁盘存储数据，并支持高效访问（如索引） | 表数据写入数据页；至少有一种持久化索引；重启后仍能查询 |

## 2. 本组建议的最小可交付版本（MVP）

### 2.1 数据与 SQL

- 一个数据库目录可包含多张表；表名、列名不区分大小写并统一转为小写，字符串值保留大小写。
- 列类型：`INT`（有符号 64 位整数）和 `TEXT`（UTF-8，最多 255 字节）。每行每列必须提供值；MVP 不支持 `NULL`、默认值、主键、外键和约束。
- 支持的语句形式如下；末尾分号可选，字符串用单引号，字符串内的单引号写成两个单引号。

```sql
CREATE TABLE students (id INT, name TEXT, score INT);
CREATE INDEX idx_students_id ON students (id);
INSERT INTO students VALUES (1, 'Alice', 90);
SELECT id, name FROM students WHERE id = 1;
SELECT * FROM students WHERE score >= 60;
UPDATE students SET score = 95 WHERE id = 1;
DELETE FROM students WHERE id = 1;
```

- `SELECT` 只查单表；列清单为 `*` 或逗号分隔的列名。`WHERE` 最多一个条件，格式为 `列名 运算符 字面量`，运算符为 `=`, `!=`, `<`, `<=`, `>`, `>=`。`UPDATE`、`DELETE` 同样接受零或一个 `WHERE` 条件；无条件时作用于全表。
- `INSERT` 按建表时的列顺序提供所有值；`UPDATE` 一次只修改一个列。`CREATE INDEX` 一次只索引一列，允许重复键；同一表同一列最多一个索引。
- `=` 条件有索引时使用索引候选行，再由执行器复核条件；其他条件全表扫描。无需实现成本估计、连接、排序、聚合或 SQL 标准全集。

### 2.2 行为约定

- `CREATE`、`INSERT`、`UPDATE`、`DELETE` 成功后返回影响行数；`SELECT` 返回列名和行值。结果行顺序未定义，测试时不要依赖插入顺序。
- 不存在的表/列、列数不对、值类型不符、语法错误应给出可理解的错误，不得静默成功。
- 正常退出时刷新缓存和索引；重新启动程序后可读到已成功执行的写入。MVP 不承诺异常断电恢复、事务原子性或多进程并发。
- 索引必须在 `INSERT`、`UPDATE`、`DELETE` 后保持正确；索引查询与全表扫描应给出同样的数据结果。
- CLI 支持交互输入、执行 SQL 脚本和明确退出；执行一条错误语句后，进程仍可继续处理下一条。

## 3. 非目标与可选增强

不纳入 MVP：多表 `JOIN`、子查询、`ORDER BY`、`GROUP BY`、事务、权限、网络协议、并发控制、崩溃恢复、完整 SQL 语法。只有在 MVP 集成与测试完成后才考虑范围查询索引、批量导入、统计信息或图形界面。增强功能不得改变已冻结接口的基本语义。

## 4. 可验收场景

1. 创建表，插入多行，退出并重启，查询到同样的行。
2. 未建索引时执行等值查询，显示全表扫描计划；建索引后显示索引扫描计划，结果一致。
3. 重复键索引返回全部匹配行；更新索引列后旧值查不到、新值查得到；删除后索引不返回已删除行。
4. 缓存容量设小后反复访问相同页，能观察到命中、替换和脏页刷新。
5. 错误 SQL、类型错误、未知列有清晰错误；随后仍能执行正确 SQL。
