# 04 测试与提交规范

## 1. 测试层次

| 层次 | 负责人 | 必测内容 |
| --- | --- | --- |
| 存储单元测试 | A | 页读写、跨页插入、删除标记、序列化边界、LRU 替换/脏页写回、索引重复键、重启恢复 |
| 前端单元测试 | B | 六类语句解析、大小写/空格/转义、未知表列、类型不符、索引计划选择、脚本分句 |
| 执行单元测试 | C | 谓词六种运算、投影、无条件全表操作、影响行数、索引候选复核 |
| 集成测试 | C 组织，A/B 参与 | 交互与脚本运行、正常退出和重启、索引前后同结果、更新/删除索引列、错误后继续运行 |

用 `unittest` 和临时目录运行测试，避免依赖特定电脑路径。所有测试应在干净目录中可重复执行；记录 Python 版本和测试命令。建议统一命令：

```powershell
python -m unittest discover -s tests -v
python -m dbms --db .\demo_data --file .\examples\demo.sql
python -m dbms --db .\demo_data
```

## 2. 必备演示与预期

`examples/demo.sql` 应覆盖以下顺序：建表、插入至少 3 行、无索引等值查询、建索引、相同等值查询、更新索引列、验证新旧键、删除、再次验证。展示 `SeqScan` 与 `IndexEqScan` 的计划标签和相同结果。脚本后退出程序，再启动并查询以验证持久化。演示前使用新的数据库目录，避免重复建表导致失败。

缓存演示可单独写小测试：`buffer_pages=2`，访问至少 3 页并重复访问其中 1 页；断言命中数和替换数增长，关闭重启后修改的数据可读。无需在用户界面暴露内部页对象。

## 3. 测试报告建议模板

每位成员提交一段可汇总的记录：

```text
模块 / 负责人：
实现范围与核心方法：
运行环境及命令：
测试用例（输入、预期、实际、结论）：
已知限制：
修复记录：
本人实际完成的文件与任务：
```

最终报告建议包含：需求分析、总体架构、模块设计与实现、接口约定、测试方法与结果、演示截图或终端输出、真实分工、限制与改进。不要用只有“测试通过”的一句话替代测试用例和结果。
